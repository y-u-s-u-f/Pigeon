# Pigeon

A macOS email and calendar client in Rust + GPUI (`gpui-kit` 0.8, imported as `gpui`, with gpui-component). Front end only, on placeholder data in `assets/*.json`; changes live in memory. The backend comes later; `docs/ROADMAP.md` tracks every feature, its status and what it will need from the backend. Keep it updated.

## Principles

- Blazing fast and lightweight. No webviews, no heavy dependencies.
- Keyboard-centric: every action has a shortcut and shows up in ⌘K. Actions, keymap and the command table live in `src/actions.rs`.
- Minimal and flat (Linear, Superhuman). The whole window is translucent glass. Light and dark follow the system.
- YAGNI. Prefer boring, known solutions. Match the surrounding code; keep comments sparse.

## Code conventions

- Colors only from `src/theme.rs`. Text sizes, spacing, radii, hit targets, motion and focus helpers from `src/ui/style.rs`; no raw px for these.
- Give interactive elements `.role(..)` and `.aria_label(..)`.
- Don't edit `assets/*.json` unless asked. Placeholder data is generated by a Claude Haiku 5.5 agent (`anthropic/claude-haiku-5-5`).
- Before finishing: `cargo fmt`, `cargo build`, `cargo clippy --all-targets` (no new warnings), `cargo test`.

## Workflow

1. One or more `implementer` agents make the changes. If there's a lot, split by non-overlapping files.
2. A separate tester tests in Codex: the main agent runs `codex exec -m gpt-6.1-terra` in a background shell, with Codex's built-in computer use (no subagents, no Cua Driver).
3. A fresh `implementer` fixes what the tester reports. Re-test as needed.

Don't have one agent implement, test and fix in a loop. Subagents don't commit; the main agent does.

## Roadmap

`docs/ROADMAP.md` must always be current. Every change that adds, changes or removes a feature updates it in the same commit: the item's entry and status (⚪ Not done / 🟡 Partially done / 🟢 Fully linked), the section and overall counts, and new items for new features or plans the user mentions. Implementers update it with their change; the main agent checks it before committing.

## Running and testing

- Run with `scripts/run.sh` (release build, signed with the local `Pigeon Dev` identity so the Keychain keeps trusting it across rebuilds; plain `cargo run --release` works but the Keychain asks again after every build). `PIGEON_DEMO=1` runs on the placeholder data. Agents running in parallel build with their own `CARGO_TARGET_DIR` in `/private/var/folders/sc/26v_9jsx0s9_fkjttv6jzjdh0000gn/T/opencode`.
- GUI testing uses Codex's built-in computer use, scoped to Pigeon's pid and window. Launch the test copy with `open -n -a <Pigeon.app> --env PIGEON_DATA_DIR=… --env …` (a `&` child dies with Codex's shell, and computer use would launch Pigeon without the environment), then check it with `ps eww -p <pid>`. Never send input to other apps. Never change system appearance or wallpaper; test dark mode in a scratch copy.
